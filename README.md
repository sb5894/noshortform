# No-shortform

YouTube Shorts를 감지하면 자동으로 뒤로 가기를 요청하는 개인용 Android 앱입니다. 차단을 켜거나 끄고, 스크롤 차단과 진입 차단 중 하나를 선택할 수 있습니다.

**[APK 다운로드 · GitHub Releases](https://github.com/sb5894/noshortform/releases)**

현재는 **개발용(debug) 빌드에서만 관찰·차단이 동작**합니다. 설치 파일은 릴리스에 첨부된 `.apk`를 사용하세요. Android Studio는 APK 설치에 필요하지 않습니다.

## 설치하기

Android 7.0(API 24) 이상이 필요합니다. 감지 대상은 Android용 YouTube 앱이며, 브라우저나 다른 앱의 숏폼은 대상이 아닙니다. 최소 Android 버전 충족이 모든 기기에서의 정상 동작을 보장하지는 않습니다.

1. 휴대폰에서 위 **APK 다운로드** 링크를 엽니다.
2. 사용할 릴리스를 선택하고 설명 아래의 **Assets**를 펼칩니다.
3. 첨부된 `.apk` 파일을 다운로드합니다. `Source code (zip)`과 `Source code (tar.gz)`는 설치 파일이 아닙니다.
4. 다운로드한 APK를 열어 설치합니다. 설치 출처 허용을 요청하면 사용한 브라우저나 파일 앱의 **알 수 없는 앱 설치** 설정을 확인하세요.

Assets에 APK가 없다면 해당 릴리스에는 설치 파일이 첨부되지 않은 상태입니다. 다른 릴리스를 확인하거나 아래 개발자 안내에 따라 debug APK를 빌드할 수 있습니다.

## 처음 사용하기

1. **No-shortform**을 엽니다.
2. **접근성 설정 열기**를 누릅니다.
3. 시스템 접근성 설정에서 **No-shortform 이벤트 관찰**을 찾아 직접 켭니다. 메뉴 위치와 명칭은 기기에 따라 다를 수 있습니다.
4. 앱으로 돌아와 접근성 상태가 **켜짐**인지 확인합니다.
5. 원하는 **차단 방식**을 선택하고 **Shorts 차단** 스위치를 켭니다.

처음 설치하면 차단은 꺼져 있고, 차단 방식은 진입 차단으로 선택되어 있습니다. 차단이 꺼져 있어도 방식을 미리 선택할 수 있습니다. 차단 설정과 선택한 모드는 기기에 저장됩니다.

차단을 멈추려면 앱의 **Shorts 차단** 스위치를 끄세요. 이벤트 관찰까지 중단하려면 시스템 접근성 설정에서 **No-shortform 이벤트 관찰**도 꺼 주세요. 앱 안의 **정보 및 사용법**에서 상세 안내를 다시 확인할 수 있습니다.

## 두 가지 차단 방식

| 방식 | 동작과 한계 |
| --- | --- |
| 스크롤 차단 | 다음 영상으로 넘길 때 차단됩니다. 첫 영상 허용을 보장하지는 않습니다. |
| 진입 차단 | Shorts에 들어갔을 때부터 차단을 시도합니다. 첫 화면이 잠깐 보일 수 있습니다. |

두 방식 중 하나만 선택합니다. 모드 변경은 서비스를 다시 켜지 않아도 다음 이벤트부터 적용됩니다.

## 알아둘 점

- **접근성 서비스와 앱의 차단 스위치는 별개입니다.** 스위치가 켜져 있어도 서비스가 꺼져 있으면 차단할 수 없습니다.
- Shorts 후보를 감지하면 Android에 뒤로 가기를 요청합니다. 요청이 실제 화면 이탈로 이어졌는지까지 확인하는 방식은 아닙니다.
- 접근성 이벤트가 전달된 뒤 반응하므로 Shorts 화면이나 첫 프레임이 잠깐 나타날 수 있습니다.
- 첫 영상 한 개를 허용하는 기능은 아닙니다. 스크롤 차단도 첫 진입 시 감지 단서가 오면 차단될 수 있습니다.
- 연속 뒤로 가기 요청은 2초 동안 제한됩니다.
- 특정 YouTube 화면 ID에 의존하므로 기기·YouTube 버전에 따라 동작 차이가 있을 수 있습니다.
- **release 빌드에서는 관찰·차단이 동작하지 않으며 스위치와 모드 선택도 비활성화됩니다.** GitHub Releases에 게시하는 것과 Android release 빌드는 별개이며, GitHub에 debug APK를 첨부할 수 있습니다.

## 차단이 안 될 때

1. 시스템 접근성 설정에서 해당 서비스가 켜져 있는지 확인합니다.
2. 앱으로 돌아와 **Shorts 차단** 스위치가 켜져 있는지 확인합니다.
3. 스위치가 비활성화되어 있고 개발 빌드 전용 안내가 보이면 debug APK인지 확인합니다.
4. 그래도 동작하지 않으면 기기·YouTube 버전과 진입 경로에 따른 감지 차이일 수 있습니다. 모든 Shorts 진입 경로의 차단을 보장하지 않습니다.

## 개인정보와 권한

접근성 서비스는 YouTube 이벤트의 출처 뷰 ID를 확인하는 데 사용합니다. 노드 트리를 탐색하거나 화면의 텍스트·콘텐츠 설명을 읽지 않습니다.

- 화면 전체 내용, 영상 제목, 이미지 및 로그 파일을 앱에서 저장하거나 네트워크로 전송하지 않습니다.
- 인터넷 권한, Firebase, 광고 및 Analytics SDK를 사용하지 않습니다.
- 개발 빌드에서는 패키지명, 이벤트 종류, 클래스명, 출처 뷰 ID, Shorts 후보 일치 여부를 Android 개발 로그인 **Logcat**에 출력합니다. 따라서 로그를 전혀 남기지 않는 앱은 아닙니다.
- 차단 여부와 선택 모드는 기기 내부에 저장되며 해당 설정은 백업·기기 이전 대상에서 제외됩니다.

## 개발자 안내

Kotlin, Jetpack Compose, Material 3 기반의 네이티브 Android 프로젝트입니다. UI 설계와 변경 기록은 [DESIGN.md](DESIGN.md)에 있습니다.

### 직접 빌드하기

Android Studio에서 프로젝트를 열고 Gradle 동기화를 완료합니다. 프로젝트 루트의 터미널에서 다음 명령으로 debug APK를 만듭니다.

```powershell
.\gradlew.bat assembleDebug
```

생성 파일: `app/build/outputs/apk/debug/app-debug.apk`

Android Studio 터미널 밖에서 실행하는 경우 사용할 JDK와 Android SDK 경로가 설정되어 있어야 합니다.

### 빌드 및 단위 테스트

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug assembleRelease lintDebug
```

이 명령은 기기에 앱을 설치하지 않습니다. release 빌드 성공은 release에서 차단이 활성화된다는 뜻이 아닙니다.

2026-09-06 UI 변경 검증 기록:

- 단위 테스트 24개 통과.
- 디버그·릴리스 빌드 성공, 디버그 Lint 오류 0개·경고 15개.
- UI 테스트 3개와 앱 컨텍스트 테스트 1개가 Pixel 6a 에뮬레이터(Android 17) 및 SM-S931N(Android 16)에서 통과.
- 사용자는 모드 통합 버전에서 차단 꺼짐과 두 모드의 정상 동작을 확인했습니다. UI 변경 후의 위 자동 테스트는 실제 YouTube 차단 재검증을 대신하지 않습니다.

일반 영상 오차단, 추가 진입 경로, 불필요한 연속 뒤로 가기, 앱·기기 재시작 후 동작, 서비스 꺼짐의 상세 기기별 검증은 남아 있습니다. 실제 기기에서의 설치·실행·테스트·설정 변경은 소유자의 사전 허락을 받아야 합니다. 자동 기기 테스트는 대상 에뮬레이터를 명시적으로 한정하여 실행합니다.

### 감지·설정 구조

- 대상 패키지: `com.google.android.youtube`.
- 스크롤 차단: `com.google.android.youtube:id/reel_player_page_container`에 정확히 일치하는 이벤트.
- 진입 차단: 위 ID 또는 `com.google.android.youtube:id/reel_recycler`에 정확히 일치하는 이벤트. 스크롤 이벤트가 올 때까지 기다리는 방식은 아닙니다.
- 발생 후 1초가 지난 이벤트는 제외하며, 뒤로 가기 요청 사이에는 실패한 요청도 포함하여 2초 제한을 둡니다. 모드 변경이 이 제한을 초기화하지 않습니다.
- `blocking_settings`에 `enabled`와 `mode`를 저장합니다. 모드는 `LEGACY` 또는 `ENTRY`이며, 누락되거나 알 수 없는 모드 값은 `ENTRY`로 해석합니다.
- Logcat 태그: `YouTubeEventObserver`. `shortsEvidence=true`는 선택한 모드의 후보 ID 일치를 뜻하며 차단 성공 여부가 아닙니다. `false`도 일반 영상임을 확정하는 값이 아닙니다.
