# Noshortform

Kotlin 및 Jetpack Compose 기반의 개발용 YouTube 접근성 이벤트 관찰·차단 프로토타입입니다.

## 보존한 체크포인트 (main, 5669689)

- 사용자 기기에서 차단 스위치가 꺼져 있으면 Shorts를 계속 볼 수 있음을 확인했습니다.
- 차단을 켠 상태에서는 Shorts 첫 진입 시 화면이 유지됐고, 다음 영상으로 넘기면 뒤로 이동했습니다.
- 이 동작은 현재 기기의 관찰 결과이며, 의도적으로 첫 영상 한 개를 허용하도록 구현된 것은 아닙니다.
- 이전 관찰 테스트에서는 첫 진입에도 후보 ID가 나온 적이 있어, 첫 진입 차단 실패 원인은 아직 확정되지 않았습니다.

## 구현 범위

- 디버그 빌드에서 YouTube 이벤트만 처리합니다.
- 스크롤 차단은 정확한 뷰 ID `com.google.android.youtube:id/reel_player_page_container`만 사용합니다.
- 진입 차단은 위 ID와 `com.google.android.youtube:id/reel_recycler`를 사용합니다.
- 차단 설정은 기본 꺼짐이며 기기에 유지됩니다. 해당 설정은 백업에서 제외됩니다.
- 뒤로 가기 요청 사이에 2초 제한을 적용하고, 발생 후 1초를 넘긴 이벤트는 차단하지 않습니다.
- Logcat 태그는 `YouTubeEventObserver`이며 패키지명, 이벤트 종류, 클래스명, 뷰 ID, `shortsEvidence`만 출력합니다.
- 화면 내용·영상 제목·이미지·로그 파일을 저장하지 않으며 네트워크 권한과 외부 분석 SDK를 사용하지 않습니다.

## 검증

보존한 main에서는 디버그 단위 테스트 14개 및 디버그·릴리스 빌드, 디버그 Lint가 통과했습니다.
첫 진입 개선 브랜치에서는 단위 테스트 18개와 디버그·릴리스 빌드가 통과했으며, 디버그 Lint는 오류 0개와 기존 경고 16개입니다.
실제 기기의 추가 진입 경로, 중복 뒤로 가기, 재부팅 후 설정 유지 검증은 남아 있습니다.

## 첫 진입 차단 개선 (feature/block-shorts-entry)

현재 체크포인트를 GitHub main에 보존하고 별도 브랜치에서 첫 진입 차단을 개선합니다.
사용자가 제공한 첫 진입 로그에서 player-page 이벤트보다 먼저 나온 `reel_recycler`를 추가 후보로 사용합니다.
이 ID는 TYPE_WINDOW_CONTENT_CHANGED에서도 판별하므로 사용자의 스크롤을 기다리지 않습니다.
공유 UI ID나 이름에 reel이 포함된 모든 ID로 범위를 넓히지 않습니다.
진입 이벤트 순서 재생 테스트는 첫 recycler 이벤트에서 한 번 요청하고 뒤따른 이벤트를 억제하는지 검증합니다.
이는 Android의 실제 뒤로 가기 성공 여부나 화면 이탈을 검증하는 기기 테스트를 대신하지 않습니다.
다음 기기 검증은 스위치를 켜고 Shorts 탭에 진입한 뒤 터치·스크롤 없이 자동 이탈하는지 확인하는 것입니다.
이후 일반 영상 오차단, 다른 진입 경로, 5초 이상 추가 뒤로 가기 없음, 차단 꺼짐을 검증합니다.
접근성 이벤트는 화면이 나타난 뒤 전달되므로, 개선 목표는 첫 영상에서 넘김 조작 없이 자동 이탈하는 것입니다.
Shorts 화면이나 첫 프레임이 잠깐도 표시되지 않는다는 보장은 하지 않습니다.

## 모드 선택 통합 (feature/blocking-modes)

컴퓨터 검증: 단위 테스트 24개 통과, 디버그·릴리스 빌드 성공, 디버그 Lint 오류 0개·기존 경고 16개. 사용자가 통합 버전의 차단 꺼짐 및 두 차단 모드가 기기에서 정상 동작함을 확인했습니다.

- 기존 차단 스위치 아래에서 스크롤 차단과 진입 차단 중 하나를 선택합니다. 꺼짐 상태에서도 모드를 고를 수 있습니다.
- 최초 설치 시 차단 꺼짐 + 진입 차단이며, 업데이트에서는 기존 스위치 값을 유지합니다.
- `blocking_settings`의 `mode` 키에 `LEGACY` 또는 `ENTRY`를 저장합니다. 없거나 알 수 없는 값은 `ENTRY`로 해석합니다.
- 설정은 기기에 유지되고 백업에서 제외됩니다. 서비스를 다시 켜지 않아도 다음 이벤트부터 적용합니다.
- 모드 변경은 2초 중복 요청 제한을 초기화하지 않습니다.
- 기존 다섯 로그 항목을 유지합니다. `shortsEvidence`는 선택한 모드의 후보에 일치하는지이며 차단 성공 여부가 아닙니다.
- `reel_recycler` 이벤트는 스크롤 차단에서 false, 진입 차단에서 true입니다.
- 스크롤 차단은 첫 영상 한 개를 허용하는 상태 관리가 아니므로, 첫 진입에도 player-page 이벤트가 오면 차단될 수 있습니다.
- 릴리스 빌드에서는 관찰·차단이 동작하지 않으며 스위치와 모드 선택을 비활성화합니다.

추가 기기 검증 항목: 일반 영상 오차단 및 5초 추가 이동 없음, 서비스 재시작 없는 모드 전환, 앱·기기 재시작 후 설정 유지, 접근성 서비스 꺼짐. 각 항목의 개별 결과는 별도로 기록하지 않았습니다.
사용자의 두 모드 정상 동작 확인 및 통합 요청에 따라 로컬 main에 fast-forward로 통합합니다. GitHub 푸시는 포함하지 않습니다.
